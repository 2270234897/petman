## 核心问题

### ❌ 商品管理中总库存一直显示为0

**问题原因：**
1. 入库时只插入了 `stock_in_detail` 记录
2. **没有更新** `spec.总库存` 字段
3. 前端从API获取商品时，`总库存`字段为空或0
4. 导致商品管理页面计算总库存时结果为0

**影响范围：**
- ❌ 商品列表中的"总库存"显示错误
- ❌ 规格详情中的库存数量错误
- ❌ 无法准确掌握库存情况

### 2. 历史数据同步 📊

由于之前的入库记录没有更新库存，需要执行数据库脚本进行同步。

**文件：** `database/sync_stock_from_records.sql`

```sql
-- 1. 重置所有库存为0
UPDATE spec SET 总库存 = 0;

-- 2. 根据入库记录重新计算
UPDATE spec s
SET 总库存 = (
    SELECT COALESCE(SUM(sid.quantity), 0)
    FROM stock_in_detail sid
    WHERE sid.spec_specID = s.specID
);
```

**执行方式：**
```powershell
# 方式1：运行PowerShell脚本（推荐）
.\sync_stock.ps1

# 方式2：手动执行SQL
mysql -u root -p < database/sync_stock_from_records.sql
```

## 库存管理逻辑说明

### 库存来源
```
spec.总库存 = Σ(所有该规格的入库数量) - Σ(所有该规格的出库数量)
```

### 库存更新时机

| 操作 | 库存变化 | 实现位置 |
|------|----------|---------|
| 新增入库单 | ✅ 增加库存 | `add_stock_in()` |
| 删除入库单 | ✅ 减少库存 | `delete_stock_in()` |
| 更新入库单 | ✅ 先减旧增新 | `update_stock_in()` |
| 新增出库单 | ⚠️ 待实现 | - |

## 数据验证SQL

### 查看库存与入库记录对比
```sql
SELECT 
    s.specID,
    p.product_name,
    s.spec_name,
    s.总库存 as current_stock,
    COALESCE(SUM(sid.quantity), 0) as should_be_stock
FROM spec s
JOIN product p ON s.product_productID = p.productID
LEFT JOIN stock_in_detail sid ON sid.spec_specID = s.specID
GROUP BY s.specID, p.product_name, s.spec_name, s.总库存
HAVING current_stock != should_be_stock;
```

如果查询结果为空，说明库存数据一致！✅

## 常见问题 FAQ

**Q: 为什么要先同步历史数据？**  
A: 之前的代码没有更新库存，所以已有的入库记录对应的库存都是0。需要先同步历史数据。

**Q: 同步会影响现有数据吗？**  
A: 只会更新 `spec.总库存` 字段，不会影响入库记录、商品信息等其他数据。

**Q: 如果同步后库存还是不对怎么办？**  
A: 运行上面的"数据验证SQL"，找出哪些规格的库存不一致，手动检查入库记录。

**Q: 出库记录会影响库存吗？**  
A: 当前版本暂未实现出库对库存的影响，这个功能需要后续添加。

**Q: 库存可以为负数吗？**  
A: 理论上不应该，但代码允许（使用COALESCE确保不会出现NULL）。建议添加约束。

## 性能考虑

### 同步脚本性能
- 数据量小（<1000规格）：< 1秒
- 数据量中（1000-10000规格）：1-5秒
- 数据量大（>10000规格）：5-30秒

### 实时更新性能
- 每次入库/更新/删除：额外1-2个UPDATE查询
- 性能影响：可忽略（<10ms）
- 建议：定期清理历史入库记录
